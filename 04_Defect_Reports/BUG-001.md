# BUG-001 Failed payment leaves funds deducted

**Environment:** Isolated missing-refund variant used for a seeded defect exercise  
**Related cases:** DRILL-01 and TC-16  
**Severity:** High because the available balance is incorrect after a failed payment.  
**Status:** Reproduced in the seeded variant. Corresponding check passed in Demo v1.0.

## Reproduction

1. Run `python 05_Test_Automation/run_ui_cases.py`. The runner executes DRILL-01 with the seeded variant. It signs in as Alice with a ₹500 balance.
2. The runner enters ₹200 and clicks **Start payment**. It observes Pending and a ₹300 available balance.
3. It selects the pending transaction and clicks **Fail selected payment**.
4. It reads the final balance and status from the wallet UI.

## Observations

| | Payment TX-0001 | Available balance |
|---|---|---:|
| Expected after failure | Failed | ₹500 |
| Actual in seeded variant | Failed | ₹300 |
| Same scenario in Demo v1.0 | Failed | ₹500 |

The seeded variant intentionally removes the refund from the available balance. The failure was observed during execution of that variant. The normal app restores the reserved amount.
